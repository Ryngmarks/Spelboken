# WO-03 handoff – PitchSpec seam, touch hit areas, ghost of previous step

**Status:** DONE · implementer (Claude Sonnet 5.5) · 2026-10-29

- **Investigated / changed:**
  - `PitchSpec` (length, width, penalty/goal area, goal width, spot, circle radius) + `DEFAULT_PITCH` 105×68; `corridorsFor`/`thirdsFor`; `clampToPitch(p, margin, pitch)`. `PitchView` and `EditorPitch` take `pitch?: PitchSpec`; viewBox, markings, guides and portrait transform come from it.
  - Pure `hitTest.ts` in screen px: entity hit radius ≥ 22 px, arrow hit stroke ≥ 44 px, nearest centre wins, snap 24 px. `EditorPitch` measures px/m from `getScreenCTM` (ResizeObserver), sizes invisible hit circles/strokes in `PitchView` from it, resolves entity pick by nearest centre on pointer-down, and snaps in client px. Pointer capture and pointerId logic untouched.
  - Ghost: `PitchView` `ghostPositions` draws faint dashed circles (`pointer-events: none`); `EditorPitch` passes the previous frame's positions when `frameIndex ≥ 1`.
- **Decisions taken:** `PITCH_LENGTH/PITCH_WIDTH` still exported (derived from `DEFAULT_PITCH`) because `Editor.tsx`, `scenario.ts`, `formations.ts`, `suggestions.ts`, `types.ts` outside my allowed files use them; the two components themselves no longer read them. Arrow hit uses today's straight chord (curves are WO-07). Hit stroke is a screen-px minimum on the invisible path only (drawn width untouched). Player hit circle only added when `pxPerMetre` is known, so the read-only player view is unchanged. Crowd fallback/cycling not built (not in this WO).
- **Files:** changed `src/domain/pitch.ts`, `pitch.test.ts`, `src/components/PitchView.tsx`, `EditorPitch.tsx`, `src/styles.css` (rules appended); new `src/components/hitTest.ts`, `hitTest.test.ts`; this handoff.
- **Tests:** `npm test` → 10 files, 66 passed. `npm run build` → OK (tsc + vite). Includes 55×35 spec test (corridors/thirds/clamp) and hitTest tests (22 px at 3.14 and 10 px/m, nearest on overlap, 44 px arrow stroke, 24 px snap).
- **Visual check:** built HEAD in a temp worktree and this branch; Chrome (playwright-core) at 1280×900, new scenario: pitch SVG screenshot of step 1 is byte-identical to baseline. Step 2 after dragging a player shows the ghost at the old position (screenshot viewed). At 375 px width the player hit circle measured 22.0 px radius. Servers/worktree/scratch removed.
- **Known problems:** Real-device touch (22 players, crossing arrows) not tested — only desktop Chrome with mouse (unverified). `EditorPitch` has no component tests (no DOM test setup in repo). A tap on an arrow right next to a player goes to the player (entities win over arrows).
