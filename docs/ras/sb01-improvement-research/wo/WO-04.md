## Requirements
1. Optional link fields on arrows exactly as blueprint §3 specifies (entity id, `targetId` for a pass receiver, …).
2. `planMove` (pure) per blueprint §2.1: creates step k+1 if missing; moves < 2 m create no arrow; arrow type from what is
   dragged (ball onto a teammate = pass with `targetId`, ball into space = pass to a point, player holding the ball =
   dribble, other player = run); the ball follows the receiver, also if the receiver is moved later; exported constant
   `BALL_FOLLOWS` (true) with a tested false path; removing a link returns the entity to its previous position.
3. `reconcileLinks` keeps the invariants; `insertFrameAfter`, `removeFrame`, `moveFrame`, `removeEntity`,
   `duplicateScenario` call it or otherwise keep links valid (ids remapped on duplicate).
4. `validate.ts` accepts the new optional fields and drops invalid ones (dangling ids, `targetId` on a non-pass, NaN)
   without rejecting the scenario.
